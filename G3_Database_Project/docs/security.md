# Verification and security

Native roles: market_client, market_freelancer, market_payment, market_analyst. No ROLE or USER_ROLE business table is added. Client/freelancer roles get specific EXECUTE grants only. Analyst gets the three aggregate views and cannot see user hashes. Native per-user accounts client_N/freelancer_N must match their users.user_id discriminator. Definer APIs authenticate with USER() (connection principal), not CURRENT_USER() (definer principal), and validate ownership. SQL parameters alone are not trusted identity. Accounts are localhost-only and locked by default; configure secrets locally, never in scripts. payment_service alone records provider statuses; real provider integration remains outside scope. Analyst aggregate access spans all clients intentionally; it is a reporting role, not a tenant role.

07_security.sql has GRANT, SET DEFAULT ROLE and REVOKE, including a temporary skill SELECT grant followed by revocation. Security tests use random ephemeral passwords in memory, verify actual denied/allowed statements, then lock accounts. Definer APIs own standalone transactions; do not invoke inside caller-owned transactions. They explicitly SET TRANSACTION ISOLATION LEVEL READ COMMITTED before START TRANSACTION. Do not switch isolation mid-transaction. Direct DBA writes must use READ COMMITTED and obey the documented parent lock order; triggers reject ordinary unsupported session isolation. DBA privileges can intentionally bypass protections and are outside application guarantees. Do not use root as an application account. Deployment should provision a dedicated definer with only necessary table/trigger privileges; local validation used root as bootstrap/definer.

Parameterize application SQL; no dynamic SQL is used. Keep hashed-password computation in a future authentication layer, use Argon2id/bcrypt with per-user salts; demo strings are deliberately not login credentials. Restrict host access, apply TLS to remote TCP accounts and configure encryption at rest/backups according to deployment facilities. TLS and at-rest encryption have not been certified in this local exercise. Retain payment records; use audit logs outside the11 business entities where required operationally. A production provider must supply external idempotency references; the current rule prevents multiple successful DB records, not multiple external debits.

Backup target: daily encrypted mysqldump --single-transaction --routines --triggers and regular restore drills, RPO24h, RTO4h as project targets. These are not demonstrated availability claims. On deadlock1213/lock timeout1205, the future application should retry the entire short transaction with bounded backoff, not a partially completed action. No deadlock occurred in the supplied concurrency checks. Do not grant DROP, ALTER, direct UPDATE/DELETE or access to password_hash to client/freelancer roles.
